# تعليمات البناء — نظام متابعة التراخيص والتجديدات

هذا الملف موجّه لـ Claude Code. اقرأه كاملًا قبل كتابة أي سطر.

---

## ما هذا المشروع

منتج SaaS متعدد المستأجرين يتابع تواريخ انتهاء التراخيص والشهادات
والعقود في المنشآت الصغيرة السعودية، ويرسل تنبيهات مبكرة قبل وقوع
الغرامة. الواجهة عربية بالكامل واتجاهها RTL.

الجملة التي يُباع بها: **غرامة واحدة تساوي اشتراك خمس سنوات.**

---

## التقنيات

مستودع npm workspaces، بنفس أسلوب مشروع `bedayah2030`:

| الحزمة | التقنية | المنفذ |
|---|---|---|
| `apps/api` | NestJS 11 | 4000 |
| `apps/web` | Next.js 16 + React 19 + Tailwind 4 | 3000 |
| `packages/db` | PostgreSQL 16 + Prisma 6 | — |
| `packages/shared` | Zod (عقود مشتركة) | — |
| الطابور | BullMQ + Redis 7 | 6379 |

المصادقة: Argon2id + JWT مع تدوير refresh token — انسخ نمطها من
`bedayah2030` بدل إعادة تصميمها.

## المهام المطلوبة منك، بالترتيب

### ١. تجهيز الهيكل
- أنشئ مستودع npm workspaces وضع الملفات في مسـاراتها أعلاه
- `docker-compose.yml` فيه Postgres 16 و Redis 7
- `.env.example` بكل المتغيرات المذكورة في `reminders.module.ts`
- ثبّت: `@nestjs/schedule @nestjs/bullmq bullmq nodemailer @umalqura/core date-fns date-fns-tz`

### ٢. قاعدة البيانات
- شغّل `prisma migrate dev --name add_license_module`
- أنشئ ترحيلًا ثانيًا باسم `license_module_hardening` وضع فيه الإضافات
  الخمس المذكورة في نهاية `sql/migration.sql` (الفهرس الفريد الجزئي،
  قيد الحامل الواحد، تريجر منع تعديل سجل الإشعارات، pgcrypto)
- شغّل ملف البذور

### ٣. المصادقة والصلاحيات
- تسجيل، دخول، إنشاء مستأجر عند أول تسجيل، دعوة أعضاء
- الأدوار: OWNER / MANAGER / VIEWER
- **عزل المستأجرين عبر Prisma Client Extension يحقن `tenantId` تلقائيًا** —
  لا تعتمد على تذكّر المطوّر في كل `findMany`. هذا شرط غير قابل للتفاوض.

### ٤. واجهات الـ API الناقصة
```
GET    /licenses                  قائمة مع فلاتر (فرع، نوع، حالة، بحث)
GET    /licenses/:id              التفاصيل + سجل الفترات + سجل التنبيهات
POST   /licenses/:id/renew        يغلق الفترة الحالية وينشئ فترة جديدة
PATCH  /licenses/:id              تعديل البيانات الأساسية
GET    /dashboard/summary         أعداد كل حالة + أقرب ١٠ انتهاءً
CRUD   /facilities  /persons  /license-types
GET    /license-types             الكتالوج (العام + الخاص بالمستأجر)
POST   /admin/reminders/run       تشغيل يدوي للمجدول (SUPER_ADMIN فقط)
```

قاعدة التجديد الحرجة: **لا يُعدَّل سجل فترة قديم أبدًا.** التجديد يضبط
`isCurrent = false` و `closedAt` على الفترة الحالية، ثم ينشئ فترة جديدة.

### ٥. شاشات الواجهة
1. **لوحة القيادة** — أربع بطاقات بالألوان، شريط زمني ٩٠ يومًا، جدول
   "يحتاج انتباهك"، وتنبيه علوي إن فشل إرسال أي إشعار
2. **قائمة التراخيص** — فلاتر وبحث وإجراءات سريعة من الصف
3. **صفحة الترخيص** — ثلاثة تبويبات: البيانات، سجل الفترات، سجل التنبيهات
4. **الإدخال السريع** — موجودة، اربطها فقط
5. **الفروع والأشخاص**
6. **الإعدادات** — مهل التنبيه، القنوات، المستخدمون

### ٦. الاختبارات
ابدأ بـ `parsers.ts` — ملف خالص بلا حالة وأكثر ما سينكسر:
- صيغ التاريخ: `2027-03-15` · `15/3/2027` · `١٥-٠٣-١٤٤٨` · `1448/03/15`
- الأرقام العربية والفارسية
- مطابقة النوع: "بلدية" · "رخصه بلديه" · "سجل تجاري" · نص لا يطابق شيئًا

ثم أربعة اختبارات للمجدول موصوفة في نهاية `reminders.module.ts`.

## قواعد ثابتة لا تخالفها

1. **التواريخ**: كل تاريخ انتهاء يُخزَّن كمنتصف ليل UTC تمثيلًا ليوم
   تقويمي. طبّق `normalizeExpiryDate` على كل مدخل. مخالفة هذا تنتج
   تنبيهات متأخرة يومًا بشكل عشوائي.
2. **`NotificationLog` للإضافة فقط** — لا تكتب أي كود يعدّله أو يحذفه.
3. **الواجهة كلها عربية RTL** بلا استثناء، والتواريخ تُعرض ميلادية
   وهجرية معًا حين يتوفر الهجري.
4. **لا تخزّن رقم الهوية أو الإقامة بلا تشفير.**
5. **لا نجاح جزئي في العمليات الجماعية** — إما الكل أو لا شيء.
